积分规则Point System

总积分公式：Sfinal = (Σ Strade × Ei) × Mhold × Bteam。 展示积分 = 原始积分 × 100，排行榜与段位门槛均使用展示积分。

积分计算粒度：按日结算。每日 UTC 00:00 计算前一日（UTC 00:00–23:59）的净买入与卖出， 应用当日早鸟乘数，得到当日交易积分，累加后得到总交易积分。

Strade = (Vnet buy × 1.2 + Vsell × 0.3) / 100。 净买入权重 1.2，卖出权重 0.3，单笔最低门槛 20 USDC。

净买入定义：当日总买入 − 当日总卖出，仅正值部分计分。若为负值，则净买入按 0 计。
示例：某日买入 500 USDC、卖出 200 USDC，净买入 300 USDC。 S = (300 × 1.2 + 200 × 0.3) / 100 = 4.2 原始积分 = 420 展示积分。

防女巫押金Anti-Sybil Deposit

用户以 20 USDC 等值 $财神到 作为押金报名，进入白名单后才开始积分计算。 押金机制同时具备三重作用：拦截批量女巫、锁定流通盘、抑制活动期间砸盘。

退还基准
按结束币价折算
01 报名锁定：20 USDC 等值 $财神到，按报名时币价锁定代币数量。
02 正常退还：活动结束后 7 天内，按结束币价折算退还等值 20 USDC 的代币。
03 违规没收：女巫/对敲违规，押金转入销毁地址或奖池，并在活动页面公示脱敏记录。

押金对奖池的保护作用
假设 500 人报名，每人锁定 20 USDC 等值 $财神到，总锁定 10,000 USDC 等值。 若 10% 被判定违规没收，1,000 USDC 等值 $财神到 打入销毁地址。 净锁定量 9,000 USDC 等值，直接减少活动期间的市场卖压。

技术架构Tech Architecture

采用 Web2.5 架构：链上数据监听 + 链下 PostgreSQL 积分计算 + 前端只调用自有后端。 避免“纯链上”计算积分导致的 API 账单爆炸和前端卡顿。

数据流
4 层
01 报名层：连接钱包 → 防女巫检查 → 质押押金 → 白名单写入 PostgreSQL。
02 捕获层：Helius Webhook 监听白名单地址交易，Parse API 解析 Jupiter/Raydium/Orca 交易。
03 计算层：后端积分引擎，每日 UTC 00:00 快照持仓，更新持仓乘数。
04 展示层：前端调用后端 API 获取排行榜/积分/奖励，零链上 RPC 调用。
核心组件
5 项
组件用途
Helius Parse API解析 Jupiter/Raydium/Orca 交易
Helius Webhooks实时监听白名单地址交易
Bitquery每日历史余额快照备用
PostgreSQL用户、积分、战队、持仓数据
Anchor 质押合约$财神到 押金锁定与退还

成本控制：白名单准入 + 动态分层快照（活跃每日，潜水每 3 天，沉睡暂停）+ Webhook 本地拦截。 数千人规模，Helius + Bitquery 月成本约 $100–200。

风控体系Risk Control

女巫攻击
押金 20 USDC + 历史交易 ≥ 10 笔 + SOL ≥ 0.01 + 钱包年龄 ≥ 7 天。
对敲刷量
10 分钟内买卖金额偏差 < 5% 视为对敲，积分清零并标记。
战队作弊
同 IP/资金来源限制，超 30% 女巫取消整队资格，没收队长押金。
流动性不足
上线前准备 DEX 初始深度，防止少量买入造成价格虚高被套利砸盘。
合规风险
不用“保证收益”，规则、奖池、发放时间全部透明。
币价剧烈波动
结束日 24h TWAP 折算，设置总流通量 3% 代币发放上限。

风险提示：加密资产风险极高，代币价格波动剧烈。本方案所有 USDC 等值奖励仅作展示参考， 最终以链上实际发放数量为准。请遵守当地法律法规，仅以可承受损失的资金参与。
